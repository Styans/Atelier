# Журнал архитектурных решений (ADR)

Формат: контекст → решение → последствия. Статусы: **Принято** (согласовано с владельцем
продукта), **Предложено** (ждёт решения), **Заменено ADR-NNN**.
Ломающие изменения контракта плагинов, новые роли и новые зависимости — только через этот файл.

## ADR-001. Монорепо на uv workspace, Python 3.12, сборка uv_build — Принято (2026-10-21)
**Контекст.** SPEC §5: Python 3.11+, uv, workspace-пакеты. На машине системный Python 3.14,
в Blender 5.2 — 3.13, Pygmalion — 3.12.
**Решение.** `.python-version` = 3.12 (uv ставит свой CPython), `requires-python >= 3.12`.
Workspace: `packages/*`, `plugins/*`, `apps/cli`; корень — виртуальный (`package = false`).
`plugins/pygmalion` исключён из workspace. Бэкенд сборки — `uv_build`.
**Последствия.** Один `uv.lock`, editable-установка всех пакетов; плагины с тяжёлыми
зависимостями живут вне workspace (ADR-011).

## ADR-002. mypy strict для всего ядра — Принято (2026-10-21)
**Контекст.** SPEC §5 требует strict минимум для `domain` и `show_engine`.
**Решение.** `strict = true` для всех пакетов `packages/*/src`, `apps/*/src` и `tests`.
Исключение: скрипты внутри Blender (`atelier_blender_bridge/scripts/`) — они работают в Python
Blender с `bpy`. Обёртки плагинов вокруг нетипизированных библиотек ослабляются точечно
через overrides с комментарием.

## ADR-003. Анимационные примитивы — плагины; строгий union строит реестр — Принято (2026-10-21)
**Контекст.** SPEC §7 просит discriminated union параметров треков; SPEC §4.1 делает каждый
примитив плагином роли `animation_primitive`. Закрытый `Literal` в `domain` ломает расширяемость.
**Решение.** `AnimTrack.primitive: str` (id компонента, напр. `builtin.rotate`) + `params: dict`.
`plugin_host` собирает из схем зарегистрированных компонентов JSON Schema `oneOf` с
дискриминатором `primitive`; он используется при загрузке шоу (валидация params) и как
tool-схема для LLM. Регионы (`all`/`plane_split`/`box`) — union в `domain`, общий для всех.
**Последствия.** Новый примитив появляется в UI и у ассистента без правок ядра; шоу со
ссылкой на отключённый примитив открывается с предупреждением.

## ADR-004. Назначение дронов — внутри роли `transition_planner` — Принято (2026-10-21)
**Контекст.** SPEC §8.3 описывает венгерский алгоритм в `show_engine`, §4.1 — роль
`transition_planner` (`builtin.hungarian_direct`).
**Решение.** Планировщик получает старт `[D,3]` и цели `[D,3]` (без назначения), возвращает
`assignment[D]` + траекторию перехода. Ядро только переиндексирует последующие кадры.
**Последствия.** Умный планировщик (staggered, via_layer, внешний) подключается без правок ядра.

## ADR-005. `TransitionSpec.style` → `planner` — Принято (2026-10-21)
**Решение.** `TransitionSpec(duration_s: float | None, planner: str | None, params: dict)`;
`planner=None` — компонент из `pipeline.transition_planner`. `style` из эскиза SPEC §7 убран.

## ADR-006. Дополнения схемы `Show`; 30 fps; музыка в v1 — Принято (2026-10-21)
**Контекст.** Эскиз SPEC §7 не содержит pipeline/артефактов; владелец выбрал 30 fps и музыку в
первой версии.
**Решение.** `Show` получает `schema_version`, `seed`, `pipeline`, `artifacts`, `audio`,
`flight` (высота взлёта, скорости взлёта/посадки); `fps = 30`. Музыка в фазе 1 — материал шоу:
файл, длительность, смещение старта относительно t=0 шоу, бюджет времени, звуковой стрип в
`.blend` (MP3 — Skybrush встраивает в `.skyc` только MP3), копия в экспорт-пакете. Волна на
таймлайне — фаза 2, биты — фаза 6.

## ADR-007. Пресеты флота — Принято (2026-10-21)
**Контекст.** Точных характеристик флота нет; владелец хочет выбирать пресет в работе.
**Решение.** Встроенные пресеты `conservative` (гор 4, вверх 2, вниз 1.5 м/с; 2 м/с²;
высоты 2.5–120 м; сетка 3 м; дистанция 2 м) и `skybrush_default` (10 / 2 / 2 м/с; 4 м/с²;
потолок 150 м; дистанция 3 м) + пользовательские в `atelier.toml [fleet_presets.*]`.
`FleetSpec` в шоу хранит значения и имя пресета-источника; `atelier fleet use/set`.

## ADR-008. Плотность формаций по умолчанию √2·d_min — Принято (2026-10-21), проверено в фазе 1
**Проверка (2026-10-22).** Property-тест `test_capt_spacing_keeps_transitions_safe` (сетки с шагом
√2·d при случайных поворотах и сдвигах): сближений ближе d нет. Эталонное шоу на 150 дронов:
минимальная дистанция за всё шоу 2.10 м при d = 2 м, без нарушений.

**Контекст.** CAPT (Turpin, Michael, Kumar, 2014): при назначении, минимизирующем сумму
квадратов расстояний, и синхронных прямолинейных траекториях дроны не сближаются ближе 2R,
если старт и цель разнесены не менее чем на 2√2·R. При R = d_min/2 это шаг ≥ √2·d_min.
**Решение.** `min_safe_scale` по умолчанию целится в шаг √2·d_min (≈ 2.83 м при 2 м);
множитель настраивается до 1.0 (тогда сближения в переходах ловит валидатор).
**Последствия.** Фигуры на ~41% крупнее минимально возможных, зато прямые переходы безопасны
по построению. Проверить на эталонном шоу в фазе 1.

## ADR-009. Соглашения: координаты, цвета, единицы — Принято (2026-10-21)
**Решение.** Z-up, метры, правая система; зритель по умолчанию на `-Y`, «перед» модели
смотрит на зрителя. GLB (Y-up, лицо на +Z) при импорте переводится в Z-up (лицо на −Y).
Цвета внутри — линейные float [0,1]; на экспорт — sRGB 8 бит. Время — секунды (float),
кадры — int при `Show.fps`.

## ADR-010. Skybrush: свои траектории и валидатор, `.blend` локально — Принято (2026-10-21)
**Контекст.** `docs/SKYBRUSH_NOTES.md`: все экспорты аддона идут через сервер; бесплатный —
≤ 64 дронов; лицензии нет.
**Решение.** Траектории, переходы, валидация — наши. Blender headless собирает `.blend`
(дроны из шаблона Skybrush, ключи `location`/`color`, сторибординг MANUAL
TAKEOFF/SHOW/LANDING, пороги safety из `FleetSpec`, звук). Свой экспорт `builtin.csv`
(zip по файлу на дрона, формат импорта Skybrush). Экспорт `.skyc` — отдельный экспортёр,
доступный при наличии сервера; на community-сервер — только по явной команде.
**Открыто.** Путь к `.skyc` без лицензии (свой писатель по libskybrush, конвертер аккаунта,
лицензия) — исследование после фазы 1.

## ADR-011. Плагинный контракт v1 — Принято (2026-10-21)
**Решение.** Плагин = папка с `atelier-plugin.toml` (поля SPEC §4.1 + необязательный
`namespace`). Компонент = реализация одной роли; id = `<namespace>.<name>` (встроенные —
`builtin.*`); плагин с одним компонентом на роль адресуется по id плагина. Роли
`animation_primitive` и `color_effect` вызываются один раз на трек по всем кадрам.
Subprocess: JSON-RPC 2.0, NDJSON по stdio, большие данные — файлами; SDK отдаёт протоколу
дубликат настоящего stdout, а fd 1 перенаправляет в stderr. Подробности —
`docs/ARCHITECTURE.md`, раздел «Плагинный контракт».

## ADR-012. Provenance: stale вычисляется, файлы неизменяемы — Принято (2026-10-21)
**Решение.** Хост (не плагин) регистрирует `ArtifactRecord` с fingerprint =
sha256(канонический JSON: компонент, версия плагина, параметры, seed, fingerprints входов) и
`content_hash` по содержимому массивов (байты npz недетерминированы из-за меток времени zip).
`stale` не хранится: артефакт устарел, если ожидаемый fingerprint его слота (из текущего
`pipeline`, переопределений и актуальных входов) отличается от записанного. Файлы
пишутся новой версией (`points_150_<fp8>.npz`), никогда не перезаписываются.

## ADR-013. Pointille — git-зависимость на ветку `atelier-integration` — Принято (2026-10-21), уточнено 2026-10-22
**Решение.** Ядро Pointille 0.9.0 закоммичено (с согласия автора) в ветку `atelier-integration`
репозитория Pointille (коммит `468fa98`), не трогая `main` и worktree. `plugins/pointille` зависит от
`pointille = { git = "file:///C:/Users/Beacon/Repo/Pointille", branch = "atelier-integration" }`;
`uv.lock` фиксирует коммит. Обновление: `uv lock --upgrade-package pointille`. Вместо editable
path-source из исходной версии ADR: рабочую копию переключать не нужно, версия воспроизводима, а коммит
Pointille входит в версию компонента (обновление делает точки stale). Адаптер хранит V/F меша;
`evaluate` — в SDK.

## ADR-014. Pygmalion — subprocess-плагин поверх `JobManager` — Принято (2026-10-21), реализовано в фазе 2
**Решение.** Не HTTP-сервер, а stdio-shim на `atelier_plugin_sdk.serve` в venv Pygmalion
(`runtime\venv`), использующий `JobManager` как библиотеку. Облачный провайдер — интерфейс-

- `typer` — CLI (фаза 0).
- `soundfile` (BSD, libsndfile: WAV/FLAC/OGG/MP3) — длительность музыки, позже волна (фаза 1).

## ADR-016. Уточнения контракта v1 по итогам фазы 1 — Принято (2026-10-22)
Контракт ещё не выпускался, поэтому правки внесены без смены `api_version`:
- `animation_primitive.evaluate` принимает `points[T, N, 3]` (состояние после предыдущих треков), а не
  `rest[N, 3]`: иначе треки не компонуются.
- `validator_rule.check` возвращает `RuleResult(violations, metrics, truncated)`: отчёту нужны метрики
  («минимальная дистанция 2.10 м»), а не только нарушения.
- `point_distributor.distribute` принимает `MeshRef | ContourRef`; не умеющий контуры отвечает
  `PluginError` (сужение типа в наследнике ломает LSP и mypy).
- В `RunContext` вместо `fleet` — `config` (настройки хоста: путь к Blender и т.п.); флот передаётся
  аргументом тем ролям, которым он нужен, а экспортёрам — в `CompiledShow.meta["fleet"]`.
- `PointSet.evaluate` — в SDK (общая геометрия для любого распределителя), `min_safe_scale` — в ядре
  (`show_engine.geometry`): ядро не может импортировать плагин Pointille.

## ADR-017. Нарушения — окна времени, а не кадры — Принято (2026-10-22)
Подряд идущие кадры с нарушением правила склеиваются в одно нарушение со списком всех дронов и худшим
значением; на правило не больше 500 записей (`truncated` считает остаток). Номера дронов в данных —
с нуля, в сообщениях — «Drone k», как в Blender/Skybrush. Сцену и сегмент дописывает ядро по таймлайну.

## ADR-018. Ключи в Blender прореживаются, `.blend` сверяется — Принято (2026-10-22)
Douglas–Peucker по каждой траектории (допуск 2 см и 2/255 по цвету), линейная интерполяция. Экспортёр
падает, если выборка кадров `.blend` отличается от траекторий больше чем на 5 см. Эталон: 150 дронов,
165 с — 1.3 MB `.blend`.

## ADR-019. Медленные тесты и эталон — Принято (2026-10-22)
`pytest` по умолчанию пропускает `slow` (отдельный venv плагина и т.п.; `uv run pytest -m slow`).
Тесты с Blender (`blender`) идут по умолчанию и пропускаются, если Blender не найден. Эталонное шоу
(`tests/e2e/golden_reference.json`) сверяет сегменты и хэш траекторий; осознанное обновление —
`ATELIER_UPDATE_GOLDEN=1 uv run pytest tests/e2e`.

## ADR-020. Продюсеры ядра и импорт — Принято (2026-10-22)
Импорт меша, компиляция и валидация — «продюсеры» ядра с собственной версией алгоритма
(`core_producer`, меняется осознанно), а не с версией пакета. Импортированный меш — выбор пользователя:
он всегда «текущий»; при повторном импорте меняется fingerprint и устаревают точки и всё ниже.

## ADR-021. Фигура использует весь флот — Принято (2026-10-22), временно
`ModelCard.drone_count` меньше флота пока не поддерживается (компилятор отвечает понятной ошибкой):
нужны правила для простаивающих дронов (где висят, погашены ли). Обсудить до фазы 5.

## ADR-022. SQLite через SQLModel: индекс шоу и очередь задач — Принято (2026-10-22)
Файл `.atelier/atelier.db`. Таблица `shows` — индекс (id, title, path, revision, updated_at),
обновляется слушателем `COMMIT_LISTENERS` после каждого commit; источник правды остаётся `show.json`.
Таблица `jobs` — id, show_id, kind, args, status (`queued/running/done/failed/cancelled`), progress,
message, cancel_requested, worker_pid, время, result, error, log_path. История чата — фаза 3.
Код — новый пакет `packages/jobs` (`atelier_jobs`), общий для API и worker (ADR-030).

## ADR-023. Очередь и worker — Принято (2026-10-22)
Один процесс `atelier_worker` забирает задачи по одной: `UPDATE … WHERE status='queued' … RETURNING`
(атомарно, без брокера). Прогресс пишется не чаще 4 раз в секунду. Отмена — флаг `cancel_requested`:
прогресс-колбэк бросает `Cancelled`, subprocess-плагину хост шлёт `atelier.cancel`. При старте worker
помечает `running`-задачи с мёртвым pid как `failed`; падение worker не роняет API. Лог задачи —
`projects/<id>/logs/jobs/<job>.log`. Виды задач: `points`, `compile`, `validate`, `export`,
`generate_images`, `generate_mesh`; одна GPU-задача за раз гарантирует единственный worker.

## ADR-024. SSE без брокера — Принято (2026-10-22)
`GET /api/events` раз в 300 мс читает изменения `jobs` и `shows` по `updated_at` и шлёт события
`job` и `show`; UI по ним перечитывает данные. Redis не нужен (SPEC §4.1), задержка до 0,3 с приемлема.

## ADR-025. Конкурентные правки: `base_revision` → 409 — Принято (2026-10-22)
Каждая правка шоу из UI несёт `base_revision`; если `show.json` изменился, `ConflictError` → HTTP 409,
UI перечитывает шоу и пишет «изменено в другом месте». Автор ревизии — `ui`, `worker` или `cli`.

## ADR-026. Настройки плагинов — Принято (2026-10-22)
- `atelier.toml`: `[plugin_settings.<id>]` (строки). Манифест объявляет ключи в `settings = {key =
  "описание"}` — их показывает экран «Плагины».
- Хост подставляет `{setting:key}` в `command` манифеста и передаёт процессу env
  `ATELIER_PLUGIN_SETTINGS` (JSON) и `ATELIER_SDK_PATHS` (где лежат `atelier_plugin_sdk` и
  `atelier_domain`): плагин в чужом venv импортирует SDK, ничего туда не ставя.
- Вкл/выкл из UI хранится в `.atelier/ui_settings.json` и объединяется с `plugins.disabled` из toml.

## ADR-027. Меш может быть файлом GLB — Принято (2026-10-22)
`MeshRef` может указывать на `.glb`/`.obj` (`MeshRef.is_mesh_data` различает); ядро импортирует такой
файл тем же `load_mesh_file`, что и загрузку пользователя (Y-up → Z-up). Provenance хранит, кто, с
какими параметрами и из какого концепта сделал меш. Сгенерированный меш — выбор пользователя, как
импортированный: смена настроек генератора не делает его stale, перегенерация только явная.

## ADR-028. Проигрывание в браузере: бинарные кадры — Принято (2026-10-22)
`GET …/compiled/frames?fps=10` отдаёт `uint32` длину заголовка + JSON-заголовок + массивы
(выравнивание 4 байта): positions float32, colors uint8, прорежено по времени; клиент интерполирует.
Тот же формат — у точек модели (`…/models/{mid}/points`, с расстоянием до соседа для тепловой карты).
150 дронов × 165 с при 10 fps — около 3 MB.

## ADR-029. Стек фронтенда — Принято (2026-10-22)
React 18 + Vite 5 + TypeScript + Tailwind 3; компоненты в стиле shadcn/ui копируются в репо поверх
Radix (dialog, tabs, slot); @react-three/fiber + drei (three 0.169); TanStack Query; vitest, eslint.
Пакетный менеджер — npm (Node 24 уже стоит). Версии в `package.json` закреплены точно. Формы из JSON
Schema — свой `SchemaForm` под то, что даёт pydantic (number/integer с min/max, boolean, string, enum,
`anyOf null`, кортежи), без rjsf. Строки — `apps/web/src/i18n/ru.ts` (с формами множественного числа).
Сборка `apps/web/dist` не коммитится; `atelier ui` отдаёт её как статику.

## ADR-030. Пакеты фазы 2 и слои — Принято (2026-10-22)
`packages/jobs` (`atelier_jobs`: модели SQLModel, `JobQueue`), `apps/worker` (`atelier_worker`),
`apps/api` (`atelier_api`). Это уровень `apps`: ядро (`domain … show_engine`) их не импортирует,
`tests/test_architecture.py` это проверяет. Новые зависимости (к ADR-015): `fastapi`, `uvicorn`
(API), `python-multipart` (загрузки GLB и музыки), `sqlmodel` (ADR-022); `httpx` — только dev, для
`TestClient`.

## ADR-031. Python проекта лежит в репозитории — Принято (2026-10-22)
Среда разработки (MSIX-приложение) виртуализирует AppData, и venv Atelier оказался на Python из
`runtime\test` Pygmalion. uv не разрешает `python-install-dir` ни в `pyproject.toml`, ни в `uv.toml`
проекта, поэтому CPython 3.12 ставится в `.python/` репозитория (`UV_PYTHON_INSTALL_DIR=.python uv
python install 3.12`, папка в `.gitignore`), и `.venv` создан от него. На другой машине достаточно
обычного `uv sync`.

## ADR-032. Плагин Pygmalion — Принято (2026-10-22)
- Плагин вне uv workspace, запускается Python'ом Pygmalion: `command = ["{setting:python}",
  "{plugin_dir}/bootstrap.py", "--entry", "{entry}"]`. `bootstrap.py` ставит в начало `sys.path` пути
  SDK, исходники `server_dir` (свежее, чем установленная в venv копия `dronegen_server`) и `src`
  плагина, настраивает logging в stderr (→ `.atelier/logs/pygmalion.log`). В venv Pygmalion ничего
  не ставится; коммит самого Pygmalion — на авторе.
- `pygmalion.images` (`zimage_turbo|sdxl|mock`): n картинок — n задач Pygmalion с `seed+i` (параметра
  `n` у Pygmalion нет). `pygmalion.mesh` (`hunyuan|triposr|silhouette|mock`): явный seed (у Hunyuan
  по умолчанию 1). После вызова модели выгружаются (`keep_loaded=false`), OOM → `ResourceExhausted` с
  подсказкой. Health перечисляет доступные бэкенды.
- Первый старт процесса — до 15 мин (`startup_timeout_s=900`), таймаут вызова — 1 ч.

## ADR-033. Уточнения контракта по итогам фазы 2 — Принято (2026-10-22)
Без смены `api_version` (контракт не выпускался): поле манифеста `settings`; `MeshRef` на файл меша
(ADR-027); роли `image_generator`/`mesh_generator` в `PipelineConfig` необязательны (`None` — этап не
настроен); `__version__` пакетов SDK и domain при импорте из исходников — `0.0.0+source`.

## ADR-034. Ассистент на локальной LLM — Принято (2026-10-31)
Расходится со SPEC §5 (там Claude API) по решению автора: только локальная модель.
- Провайдер `llama_server`: свой процесс `llama-server.exe` из runtime Pygmalion с весами
  Qwen3‑VL‑8B‑Instruct Q4_K_M, OpenAI-совместимый `/v1/chat/completions` со стримингом и tool calling
  (`--jinja`). Pygmalion не правим: берём только бинарь и веса по путям из `[assistant.llama_server]`
  в `atelier.toml` (`exe`, `model`, `ctx=16384`, `gpu_layers=99`, `temperature=0.4`).
- Зрение (`mmproj`) в фазе 3 не грузим — экономия видеопамяти.
- `LLMClient` — протокол с нейтральными блоками text / tool_use / tool_result. Реализации:
  `LlamaServerClient` и `ScriptedClient` (тесты). Claude подключается позже ещё одной реализацией.
- Процесс слушает только 127.0.0.1 на свободном порту и привязан к worker'у Windows job object
  (kill-on-close): после краха worker'а 6 ГБ видеопамяти не остаются занятыми.
- Пакет `packages/assistant` (`atelier_assistant`) — уровень apps, рядом с `atelier_jobs`: им
  пользуются worker, API и CLI. Расхождение со SPEC §6 («ассистент в apps/api») ради worker'а.
- Новая runtime-зависимость: `httpx` (стрим HTTP от llama-server; раньше был только dev).
- Замеры на RTX 3050: модель готова за 2,6 с, чтение промпта ~2 мс/токен, генерация ~40 ток/с;
  реальный ход 15–45 с.

## ADR-035. Ход чата — задача очереди — Принято (2026-10-31)
- Ход — задача `assistant_turn` в том же worker'е: «одна GPU-задача за раз» и модульный монолит
  соблюдаются сами собой. У задач появилось поле `priority`: ход (10) забирается раньше прочих
  ожидающих задач, но идущую не прерывает.
- Worker останавливает llama-server перед задачами с GPU (`generate_images`, `generate_mesh`) и после
  `idle_unload_s` простоя (по умолчанию 600 с). Отмена хода — обычная отмена задачи.
- `atelier chat "фраза"` выполняет тот же ход в процессе CLI (для отладки без браузера) и
  отказывается, пока идёт GPU-задача.

## ADR-036. История чата в SQLite — Принято (2026-10-31)
Таблицы `chat_messages` (show_id, роль, блоки, `turn_job_id`, `revision_before/after`),
`chat_events` (дельты текста, вызовы и результаты инструментов, статусы) и `proposals` (действие,
аргументы, статус pending/applied/dismissed). SSE `/api/shows/{id}/chat/events` опрашивает
`chat_events` раз в 150 мс, как ADR-024. В истории есть роль `notice` — сообщения для человека,
которые модели не отправляются. Откаченный ход помечается `chat_messages.rolled_back_at` (колонка
добавляется миграцией при старте) и в историю модели больше не попадает.

## ADR-037. Программу предлагает LLM, удержания подгоняет код — Принято (2026-10-31)
`propose_program` получает сцены с фигурами и желаемыми удержаниями. Код одной ревизией создаёт
карточки (одна карточка на одинаковое имя фигуры) и сцены, считает оценку таймлайна (ADR-038) и
подгоняет удержания под бюджет брифа: пропорционально, в пределах 6–40 с, сетка 0,5 с. Если даже на
минимуме не влезает — модели уходит «уберите N сцен» с цифрами. Программа предыдущего хода уже
пользовательская: её замена — только предложение (`replace_program`).

## ADR-038. Оценка таймлайна до компиляции — Принято (2026-10-31)
`show_engine.estimate` проходит программу так же, как компилятор: взлёт и посадка точно, переходы —
формулой синхронного квинтика планировщика по габаритам фигур с назначением Хангарианом; если точек
нет — плоская сетка-заглушка по размеру фигуры, плюс доля перестройки `RESHAPE_SHARE = 0.18`.
Формула повторена в ядре: ядро не импортирует плагин. На шоу приёмки фазы 2 (150 дронов) оценка в
пределах 5% от компилятора. UI и ассистент берут её из `GET /api/shows/{id}/timeline`; после
компиляции — точные значения.

## ADR-039. Правки ассистента — Принято (2026-10-31)
- Инструменты — методы `ShowService`, автор ревизий `assistant`, новых путей записи в `show.json`
  нет: `update_brief`, `propose_program`, `add_scene`, `update_scene`, `reorder_scenes`,
  `create_model_card`, `update_model_card`, `fit_to_budget` (с новой длительностью),
  `propose_action`.
- Ручные правки защищены кодом: поле сцены или карточки, изменённое человеком после прошлого
  ответа, ассистент может поменять, только если новое значение названо в текущем сообщении
  (удержания — свободно). Модель видит список таких правок в блоке «шоу сейчас».
- Если после хода шоу длиннее бюджета, код сам пишет в чат пометку с оценкой — независимо от
  того, что написала модель.
- Аргументы проверяет Pydantic, ошибка уходит модели результатом инструмента; три неудачи подряд
  или 8 шагов — ход останавливается с честным сообщением пользователю.
- Сторону зрителя модель называет словами (юг/север/запад/восток), направление считает код;
  длительность перехода модель не задаёт.
- Дорогое и удаление (точки, компиляция, проверка, экспорт, генерация, удаление сцены или карточки,
  замена программы) — только предложение с кнопкой «Применить»; одинаковое ожидающее предложение
  второй раз не создаётся.
- «Откатить ответ» — откат к `revision_before` хода новой ревизией.

## ADR-040. Контекст модели под 16K — Принято (2026-10-31)
Стабильный префикс (системный промт `system_prompt.md`, схемы инструментов, история) переиспользует
кэш llama-server. Компактное резюме шоу (`show_engine.summary`) — блоком «шоу сейчас» только в
последнем сообщении пользователя. История режется целыми ходами до ~24 000 символов. Кириллица в
сообщениях: в ruff `allowed-confusables` добавлены русские буквы, похожие на латинские.
