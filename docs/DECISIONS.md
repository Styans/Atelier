# Журнал архитектурных решений (ADR)

Формат: контекст → решение → последствия. Статусы: **Принято** (согласовано с владельцем
продукта), **Предложено** (ждёт решения), **Заменено ADR-NNN**.
Ломающие изменения контракта плагинов, новые роли и новые зависимости — только через этот файл.

---

## ADR-001. Монорепо на uv workspace, Python 3.12, сборка uv_build — Принято (2026-10-21)
**Контекст.** SPEC §5: Python 3.11+, uv, workspace-пакеты. На машине системный Python 3.14,
в Blender 5.2 — 3.13, Pygmalion — 3.12.
**Решение.** `.python-version` = 3.12 (uv ставит свой CPython), `requires-python >= 3.12`.
Workspace: `packages/*`, `plugins/*`, `apps/cli`; корень — виртуальный (`package = false`).
`plugins/pygmalion` исключён из workspace. Бэкенд сборки — `uv_build`.
**Последствия.** Один `uv.lock`, editable-установка всех пакетов; плагины с тяжёлыми
зависимостями живут вне workspace (ADR-011).

## ADR-002. mypy strict для всего ядра — Принято (2026-10-21)
**Контекст.** SPEC §5 требует strict минимум для `domain` и `show_engine`.
**Решение.** `strict = true` для всех пакетов `packages/*/src`, `apps/*/src` и `tests`.
Исключение: скрипты внутри Blender (`atelier_blender_bridge/scripts/`) — они работают в Python
Blender с `bpy`. Обёртки плагинов вокруг нетипизированных библиотек ослабляются точечно
через overrides с комментарием.

## ADR-003. Анимационные примитивы — плагины; строгий union строит реестр — Принято (2026-10-21)
**Контекст.** SPEC §7 просит discriminated union параметров треков; SPEC §4.1 делает каждый
примитив плагином роли `animation_primitive`. Закрытый `Literal` в `domain` ломает расширяемость.
**Решение.** `AnimTrack.primitive: str` (id компонента, напр. `builtin.rotate`) + `params: dict`.
`plugin_host` собирает из схем зарегистрированных компонентов JSON Schema `oneOf` с
дискриминатором `primitive`; он используется при загрузке шоу (валидация params) и как
tool-схема для LLM. Регионы (`all`/`plane_split`/`box`) — union в `domain`, общий для всех.
**Последствия.** Новый примитив появляется в UI и у ассистента без правок ядра; шоу со
ссылкой на отключённый примитив открывается с предупреждением.

## ADR-004. Назначение дронов — внутри роли `transition_planner` — Принято (2026-10-21)
**Контекст.** SPEC §8.3 описывает венгерский алгоритм в `show_engine`, §4.1 — роль
`transition_planner` (`builtin.hungarian_direct`).
**Решение.** Планировщик получает старт `[D,3]` и цели `[D,3]` (без назначения), возвращает
`assignment[D]` + траекторию перехода. Ядро только переиндексирует последующие кадры.
**Последствия.** Умный планировщик (staggered, via_layer, внешний) подключается без правок ядра.

## ADR-005. `TransitionSpec.style` → `planner` — Принято (2026-10-21)
**Решение.** `TransitionSpec(duration_s: float | None, planner: str | None, params: dict)`;
`planner=None` — компонент из `pipeline.transition_planner`. `style` из эскиза SPEC §7 убран.

## ADR-006. Дополнения схемы `Show`; 30 fps; музыка в v1 — Принято (2026-10-21)
**Контекст.** Эскиз SPEC §7 не содержит pipeline/артефактов; владелец выбрал 30 fps и музыку в
первой версии.
**Решение.** `Show` получает `schema_version`, `seed`, `pipeline`, `artifacts`, `audio`,
`flight` (высота взлёта, скорости взлёта/посадки); `fps = 30`. Музыка в фазе 1 — материал шоу:
файл, длительность, смещение старта относительно t=0 шоу, бюджет времени, звуковой стрип в
`.blend` (MP3 — Skybrush встраивает в `.skyc` только MP3), копия в экспорт-пакете. Волна на
таймлайне — фаза 2, биты — фаза 6.

## ADR-007. Пресеты флота — Принято (2026-10-21)
**Контекст.** Точных характеристик флота нет; владелец хочет выбирать пресет в работе.
**Решение.** Встроенные пресеты `conservative` (гор 4, вверх 2, вниз 1.5 м/с; 2 м/с²;
высоты 2.5–120 м; сетка 3 м; дистанция 2 м) и `skybrush_default` (10 / 2 / 2 м/с; 4 м/с²;
потолок 150 м; дистанция 3 м) + пользовательские в `atelier.toml [fleet_presets.*]`.
`FleetSpec` в шоу хранит значения и имя пресета-источника; `atelier fleet use/set`.

## ADR-008. Плотность формаций по умолчанию √2·d_min — Принято (2026-10-21), проверено в фазе 1
**Проверка (2026-10-22).** Property-тест `test_capt_spacing_keeps_transitions_safe` (сетки с шагом
√2·d при случайных поворотах и сдвигах): сближений ближе d нет. Эталонное шоу на 150 дронов:
минимальная дистанция за всё шоу 2.10 м при d = 2 м, без нарушений.

**Контекст.** CAPT (Turpin, Michael, Kumar, 2014): при назначении, минимизирующем сумму
квадратов расстояний, и синхронных прямолинейных траекториях дроны не сближаются ближе 2R,
если старт и цель разнесены не менее чем на 2√2·R. При R = d_min/2 это шаг ≥ √2·d_min.
**Решение.** `min_safe_scale` по умолчанию целится в шаг √2·d_min (≈ 2.83 м при 2 м);
множитель настраивается до 1.0 (тогда сближения в переходах ловит валидатор).
**Последствия.** Фигуры на ~41% крупнее минимально возможных, зато прямые переходы безопасны
по построению. Проверить на эталонном шоу в фазе 1.

## ADR-009. Соглашения: координаты, цвета, единицы — Принято (2026-10-21)
**Решение.** Z-up, метры, правая система; зритель по умолчанию на `-Y`, «перед» модели
смотрит на зрителя. GLB (Y-up, лицо на +Z) при импорте переводится в Z-up (лицо на −Y).
Цвета внутри — линейные float [0,1]; на экспорт — sRGB 8 бит. Время — секунды (float),
кадры — int при `Show.fps`.

## ADR-010. Skybrush: свои траектории и валидатор, `.blend` локально — Принято (2026-10-21)
**Контекст.** `docs/SKYBRUSH_NOTES.md`: все экспорты аддона идут через сервер; бесплатный —
≤ 64 дронов; лицензии нет.
**Решение.** Траектории, переходы, валидация — наши. Blender headless собирает `.blend`
(дроны из шаблона Skybrush, ключи `location`/`color`, сторибординг MANUAL
TAKEOFF/SHOW/LANDING, пороги safety из `FleetSpec`, звук). Свой экспорт `builtin.csv`
(zip по файлу на дрона, формат импорта Skybrush). Экспорт `.skyc` — отдельный экспортёр,
доступный при наличии сервера; на community-сервер — только по явной команде.
**Открыто.** Путь к `.skyc` без лицензии (свой писатель по libskybrush, конвертер аккаунта,
лицензия) — исследование после фазы 1.

## ADR-011. Плагинный контракт v1 — Принято (2026-10-21)
**Решение.** Плагин = папка с `atelier-plugin.toml` (поля SPEC §4.1 + необязательный
`namespace`). Компонент = реализация одной роли; id = `<namespace>.<name>` (встроенные —
`builtin.*`); плагин с одним компонентом на роль адресуется по id плагина. Роли
`animation_primitive` и `color_effect` вызываются один раз на трек по всем кадрам.
Subprocess: JSON-RPC 2.0, NDJSON по stdio, большие данные — файлами; SDK отдаёт протоколу
дубликат настоящего stdout, а fd 1 перенаправляет в stderr. Подробности —
`docs/ARCHITECTURE.md`, раздел «Плагинный контракт».

## ADR-012. Provenance: stale вычисляется, файлы неизменяемы — Принято (2026-10-21)
**Решение.** Хост (не плагин) регистрирует `ArtifactRecord` с fingerprint =
sha256(канонический JSON: компонент, версия плагина, параметры, seed, fingerprints входов) и
`content_hash` по содержимому массивов (байты npz недетерминированы из-за меток времени zip).
`stale` не хранится: артефакт устарел, если ожидаемый fingerprint его слота (из текущего
`pipeline`, переопределений и актуальных входов) отличается от записанного. Файлы
пишутся новой версией (`points_150_<fp8>.npz`), никогда не перезаписываются.

## ADR-013. Pointille — git-зависимость на ветку `atelier-integration` — Принято (2026-10-21), уточнено 2026-10-22
**Решение.** Ядро Pointille 0.9.0 закоммичено (с согласия автора) в ветку `atelier-integration`
репозитория Pointille (коммит `468fa98`), не трогая `main` и worktree. `plugins/pointille` зависит от
`pointille = { git = "file:///C:/Users/Beacon/Repo/Pointille", branch = "atelier-integration" }`;
`uv.lock` фиксирует коммит. Обновление: `uv lock --upgrade-package pointille`. Вместо editable
path-source из исходной версии ADR: рабочую копию переключать не нужно, версия воспроизводима, а коммит
Pointille входит в версию компонента (обновление делает точки stale). Адаптер хранит V/F меша;
`evaluate` — в SDK.

## ADR-014. Pygmalion — subprocess-плагин поверх `JobManager` — Принято (2026-10-21), фаза 2
**Решение.** Не HTTP-сервер, а stdio-shim на `atelier_plugin_sdk.serve` в venv Pygmalion
(`runtime\venv`), использующий `JobManager` как библиотеку. Облачный провайдер — интерфейс-
заглушка; сравнение сервисов — перед фазой 4.

## ADR-015. Зависимости и инструменты — Принято (2026-10-21)
- `typer` — CLI (фаза 0).
- `soundfile` (BSD, libsndfile: WAV/FLAC/OGG/MP3) — длительность музыки, позже волна (фаза 1).
- `pillow` — текстуры GLB для цветов Pointille (фаза 1).
- `numpy`, `scipy`, `trimesh`, `pydantic` — из SPEC §5 (фаза 1).
- Конфиг `atelier.toml` читается `tomllib` + Pydantic (без новой зависимости); `.env` — только
  секреты, с фазы 3.
- Проверка запрещённых импортов — свой AST-тест (`tests/test_architecture.py`), без import-linter.
- Хранилище проекта — модуль `show_engine.store`, отдельного пакета нет.

## ADR-016. Уточнения контракта v1 по итогам фазы 1 — Принято (2026-10-22)
Контракт ещё не выпускался, поэтому правки внесены без смены `api_version`:
- `animation_primitive.evaluate` принимает `points[T, N, 3]` (состояние после предыдущих треков), а не
  `rest[N, 3]`: иначе треки не компонуются.
- `validator_rule.check` возвращает `RuleResult(violations, metrics, truncated)`: отчёту нужны метрики
  («минимальная дистанция 2.10 м»), а не только нарушения.
- `point_distributor.distribute` принимает `MeshRef | ContourRef`; не умеющий контуры отвечает
  `PluginError` (сужение типа в наследнике ломает LSP и mypy).
- В `RunContext` вместо `fleet` — `config` (настройки хоста: путь к Blender и т.п.); флот передаётся
  аргументом тем ролям, которым он нужен, а экспортёрам — в `CompiledShow.meta["fleet"]`.
- `PointSet.evaluate` — в SDK (общая геометрия для любого распределителя), `min_safe_scale` — в ядре
  (`show_engine.geometry`): ядро не может импортировать плагин Pointille.

## ADR-017. Нарушения — окна времени, а не кадры — Принято (2026-10-22)
Подряд идущие кадры с нарушением правила склеиваются в одно нарушение со списком всех дронов и худшим
значением; на правило не больше 500 записей (`truncated` считает остаток). Номера дронов в данных —
с нуля, в сообщениях — «Drone k», как в Blender/Skybrush. Сцену и сегмент дописывает ядро по таймлайну.

## ADR-018. Ключи в Blender прореживаются, `.blend` сверяется — Принято (2026-10-22)
Douglas–Peucker по каждой траектории (допуск 2 см и 2/255 по цвету), линейная интерполяция. Экспортёр
падает, если выборка кадров `.blend` отличается от траекторий больше чем на 5 см. Эталон: 150 дронов,
165 с — 1.3 MB `.blend`.

## ADR-019. Медленные тесты и эталон — Принято (2026-10-22)
`pytest` по умолчанию пропускает `slow` (отдельный venv плагина и т.п.; `uv run pytest -m slow`).
Тесты с Blender (`blender`) идут по умолчанию и пропускаются, если Blender не найден. Эталонное шоу
(`tests/e2e/golden_reference.json`) сверяет сегменты и хэш траекторий; осознанное обновление —
`ATELIER_UPDATE_GOLDEN=1 uv run pytest tests/e2e`.

## ADR-020. Продюсеры ядра и импорт — Принято (2026-10-22)
Импорт меша, компиляция и валидация — «продюсеры» ядра с собственной версией алгоритма
(`core_producer`, меняется осознанно), а не с версией пакета. Импортированный меш — выбор пользователя:
он всегда «текущий»; при повторном импорте меняется fingerprint и устаревают точки и всё ниже.

## ADR-021. Фигура использует весь флот — Принято (2026-10-22), временно
`ModelCard.drone_count` меньше флота пока не поддерживается (компилятор отвечает понятной ошибкой):
нужны правила для простаивающих дронов (где висят, погашены ли). Обсудить до фазы 5.
